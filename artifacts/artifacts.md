## Build

```bash
python3 artifacts/build.py            # everything
python3 artifacts/build.py phase-2    # one phase (the Atlas is not rebuilt)
python3 artifacts/build.py ch-03      # one story chapter
python3 artifacts/build.py story      # every chapter + the contents page
python3 artifacts/build.py serial     # just the contents page
```

`build.py` fails loudly on a missing required key or a duplicate concept id. The Atlas is generated from the phase files, so a concept added to a phase appears on the map automatically — always rebuild and republish both.

## Anatomy

```
artifacts/
  build.py              generator
  artifacts.md          this registry
  data/
    atlas.json          the map: phases, concepts NOT yet captured ("ghosts"), the serial card
    phase-N.json        one phase's captured concepts, cards and reading list
    story/
      index.json        all 27 book chapters, their spot colours and published URLs
      ch-NN.json        one chapter's panels, cast and recap

  template/
    base.css            shared drafting-sheet identity (all six pages)
    phase.css           phase-sheet layout

    atlas.css           atlas layout
    atlas.body.html     atlas markup + script (__DATA__ placeholder)

```

## The notebook — Fundamentals of Software Architecture, chapter by chapter

One book chapter becomes one published artifact: a **review sheet**, not a story. It exists to be
re-scanned in under a minute, months later. The shape, in order:

1. **Cover** — chapter, title, one-sentence gist, read time.
2. **The one-minute version** — the chapter's four to six claims in a single accent-bordered card
   at the top. This is the part he actually comes back for; everything below is the detail behind it.
3. **Topics** — one infographic each, with caption-length text. The figure carries the content; the
   prose is bullets and at most one short paragraph. `"wide": true` gives a figure the full width.
4. **Quotes** — the book's actual words, marked as such, attributed, with a note on what they mean.
5. **Decisions** — the only place a scene appears. A 40-word situation, two or three options with
   what each costs, one marked `1` as the book's answer, then a verdict. Boxed and inverted so it
   reads as a different kind of thing.

Keep the whole sheet under about 900 words of prose. If a chapter needs more than that, it needs
more figures, not more paragraphs.

To add a chapter:

1. Extract the real text first — never write from memory of the book:
   `pdftotext -f <first> -l <last> -layout resources/fundamentals_of_software_architecture_a_modern_engineering.pdf -`
   (the PDF outline's page numbers are one less than pdftotext's).
2. Write `data/story/ch-NN.art.html` — one inline SVG per `<!--@ key -->` line at column 0. House
   style: `fill:none`, `stroke:var(--ink)` at 1.5–1.6, secondary lines `var(--ink3)` at 1, mono
   labels in `var(--ink2)`, and **exactly one element per drawing** carrying `var(--acc)`. Every
   drawing must carry information — if it only illustrates a scene, cut it.
3. Write `data/story/ch-NN.json`: `minute` for the top card, then `sections`. A section is a topic by
   default, `"k":"decision"` for a scene. Don't let a `cap` repeat what the drawing already says.
4. `python3 artifacts/build.py ch-NN serial` — it fails on a figure that is referenced but not drawn,
   warns about one drawn but never placed, and ships only the drawings actually used.
5. Publish the chapter, put its URL in `data/story/index.json`, rebuild and republish `story.html`.

The spot colour per chapter is already assigned in `index.json` — 27 faded accents chosen so no two
adjacent chapters look alike. `build.py` emits each as `--acc`/`--accBg`/`--accLine`/`--dot` for all
three theme states, so no component rule ever needs a raw hex.

*Output files are still named `story-NN.html`: the artifact URL is bound to the file path, so
renaming them would strand every link.*

## Design constraints for any edit

- **Theme**: colours come from the CSS custom properties in `base.css` only. Never write a raw hex in a component rule, and never define a colour solely inside a `@media` or `[data-theme]` block.
- **Self-contained**: no external requests except Google Fonts. Inline everything else.
- **`[hidden]`**: `base.css` ends with `[hidden]{display:none !important}` — it is load-bearing. Fixed overlays (`.drawer`, `.review`) set `display:flex`, which otherwise beats the browser's `[hidden]` rule and leaves an invisible panel swallowing every click.
- **Fonts**: Saira Condensed (display / title blocks), IBM Plex Sans (body), IBM Plex Mono (labels and data).
- **No `</style>` inside a `.css` file** — it ends the style block early and dumps the rest of the
  stylesheet onto the page as visible text. `build.py` now refuses to build if it finds one. (This
  actually happened: `atlas.css` carried a stray one and the published Atlas showed three CSS rules
  as text above the title block.)
- **No scroll-triggered reveals.** They leave everything below the fold blank in print, in thumbnail
  capture, and anywhere `IntersectionObserver` does not run.
- **The notes have to be findable without reading.** These sheets are revision material: the figure
  and the one-minute card must carry the chapter on their own, because that is all he will re-read.
